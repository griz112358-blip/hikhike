# 文件名编码修复说明

## 问题背景

KML文件来自不同平台（2bulu、wikiloc、Waymarked、Overpass），文件名的编码方式可能不同：
- **2bulu**: 通常使用GBK编码
- **wikiloc**: 通常使用UTF-8编码
- **Waymarked**: 通常使用UTF-8编码
- **Overpass**: 通常使用UTF-8编码

当这些文件在不同系统间传输时，可能会出现编码混用问题，导致文件名乱码。

## 修复策略

### 两层修复机制

```
原始文件名
    ↓
┌─────────────────────────┐
│ 1. iconv-lite 自动转换  │  ← 优先处理
│    (GBK → UTF-8)        │
└─────────────────────────┘
    ↓
仍有乱码？
    ↓ 是
┌─────────────────────────┐
│ 2. 映射表手动替换        │  ← 备选方案
└─────────────────────────┘
    ↓
修复后的文件名
```

### 第一层：iconv-lite 自动转换

**适用场景**：
- 文件名是完整的GBK编码，被错误地当作UTF-8读取
- 文件名是UTF-8编码，被错误地当作GBK读取
- 大多数常见的编码混用问题

**工作原理**：
```javascript
// 检测是否包含非ASCII字符
if (/[\x80-\xFF]/.test(filename)) {
  // 尝试从GBK解码
  const buffer = Buffer.from(filename, 'binary');
  const decoded = iconv.decode(buffer, 'gbk');
  
  // 如果解码结果包含中文字符，说明转换成功
  if (/[\u4e00-\u9fa5]/.test(decoded)) {
    return decoded;
  }
}
```

**优势**：
- ✅ 自动化处理，无需手动维护
- ✅ 支持多种编码格式（GBK、UTF-8、Big5等）
- ✅ 适用于大多数情况

**局限性**：
- ❌ 无法处理已经损坏的编码（多次错误转换）
- ❌ 无法处理部分字符被正确、部分字符乱码的情况

### 第二层：映射表手动替换

**适用场景**：
- 文件名已经被多次错误转换，原始编码信息丢失
- 某些特殊字符在转换过程中被损坏
- 需要精确控制某些特定乱码的修复

**工作原理**：
```javascript
// 使用预定义的映射表进行字符串替换
for (const [wrong, correct] of Object.entries(config.encodingFixes)) {
  filename = filename.replace(new RegExp(wrong, 'g'), correct);
}
```

**优势**：
- ✅ 可以处理iconv无法修复的特殊情况
- ✅ 精确控制，避免误转换
- ✅ 速度快（直接字符串替换）

**局限性**：
- ❌ 需要手动维护映射表
- ❌ 只能修复已知的乱码
- ❌ 遇到新乱码需要手动添加映射

## 实际示例

### 示例1：iconv可修复的情况

**原始文件名**（GBK编码，被当作UTF-8读取）：
```
庐山环线.kml
```

**错误显示**（当作UTF-8读取GBK字节）：
```
ÙÜÉ½环线.kml
```

**修复过程**：
```javascript
// iconv检测到乱码字符
iconv.decode(Buffer.from('ÙÜÉ½', 'binary'), 'gbk')
// → '庐山' ✅
```

**修复结果**：
```
庐山环线.kml ✅
```

### 示例2：需要映射表的情况

**原始文件名**：
```
2025-07-27 庐山环线.kml
```

**错误显示**（已经过多次错误转换）：
```
2025-07-27 ÙÜÉ½环线.kml
```

**修复过程**：
```javascript
// iconv尝试转换
iconv.decode(Buffer.from('ÙÜÉ½', 'binary'), 'gbk')
// → 仍然是乱码，因为字节已经被破坏 ❌

// 使用映射表
'ÙÜÉ½'.replace(/ÙÜÉ½/g, '庐山')
// → '庐山' ✅
```

**修复结果**：
```
2025-07-27 庐山环线.kml ✅
```

## 如何使用

### 启用调试模式

查看详细的编码修复过程：

```javascript
// 在 config.js 中设置
logLevel: 'debug'
```

**输出示例**：
```
  iconv转换: ÙÜÉ½环线.kml -> 庐山环线.kml
  映射表替换: µº -> 岛
```

### 添加新的映射

如果遇到iconv无法修复的乱码：

1. 在 `config.js` 的 `encodingFixes` 中添加映射：
```javascript
encodingFixes: {
  '乱码字符': '正确字符',
  // 例如：
  'ÙÜÉ½': '庐山'
}
```

2. 重新运行脚本

## 最佳实践

1. **优先使用iconv**：让iconv自动处理大部分情况
2. **按需添加映射**：只在iconv无法修复时才手动添加映射
3. **收集常见乱码**：将遇到的常见乱码添加到映射表
4. **定期清理映射表**：如果iconv能处理的，可以从映射表中移除

## 总结

- **第一层（iconv）**：处理90%以上的编码问题
- **第二层（映射表）**：处理剩余10%的特殊情况
- **分工明确**：iconv负责自动化，映射表负责精确控制
- **可扩展**：可以根据实际情况动态添加映射
